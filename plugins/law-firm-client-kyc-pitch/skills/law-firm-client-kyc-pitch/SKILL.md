# 律师事务所 Client KYC & Pitch Intelligence Skill

## 一、Skill定位

本 Skill 用于律师、合伙人及业务团队在接触潜在客户、准备首次拜访、投标准备、项目争取或客户关系维护前，快速形成一份兼具商业判断和法律服务视角的企业背景调查报告。

本 Skill 所称“KYC”是律师事务所内部使用的 **Client KYC / Client Intelligence**，核心目的不是完成反洗钱身份核验，也不是开展交易层面的法律尽职调查，而是帮助律师在见客户前回答以下问题：

1. 这家公司是谁，为什么现在值得关注；
2. 它真正依靠什么业务、客户和能力增长；
3. 它目前处于技术验证、商业化、扩张、融资还是上市准备阶段；
4. 谁拥有控制权，谁是关键决策人，资本方如何影响公司；
5. 它面对哪些直接竞争者、上市Benchmark和全球Top企业；
6. 它下一阶段最可能作出哪些重大商业及资本决策；
7. 哪些法律问题会伴随这些决策自然发生；
8. 律师应如何以行业理解、交易经验和跨境执行能力切入，而不是泛泛推销法律服务；
9. 第一次会面应提出哪些能够显示专业理解的高价值问题。

最终成果应接近律所合伙人、投行或咨询机构内部使用的 **Client Brief / Pitch Brief**，而不是工商数据库摘录、法律意见书或风险罗列报告。

报告虽然不是正式法律意见书，但凡作出监管、资质、许可、备案、处罚或法律风险判断，必须以报告基准日现行有效的法律依据和可核验业务事实为基础。不得以数据库中的现有证照清单代替适用法律分析，也不得从“公司有什么证”反推“公司依法需要什么证”。

## 二、不可变更的目录结构

最终报告必须严格保留以下八个一级章节，不得增删、合并、重命名或调整顺序：

1. 一、商业概况
2. 二、业务情况
3. 三、资质证照及IP
4. 四、股权结构
5. 五、融资历史
6. 六、同行业对比
7. 七、创始人及核心团队
8. 八、负面新闻

不得新增“综合结论”“免责声明”“法律服务建议”“Pitch方案”等一级章节。

律师Pitch视角应通过以下方式嵌入现有八章，而不是改变目录：

- 在事实介绍中加入商业意义；
- 在每章末尾形成简短的“商业洞察与Pitch启示”；
- 需要时以非编号提示框列示“建议会面问题”；
- 法律服务机会必须与该章事实直接关联，不得另行堆砌通用服务清单。

## 四、成功标准

报告完成后，律师应能够在约15至30分钟内掌握目标客户，并能够：

- 用两三句话准确概括公司商业定位；
- 判断公司当前发展阶段和近期核心矛盾；
- 识别其管理层、股东和投资人的主要诉求；
- 说清公司与主要竞争者相比“强在哪里、弱在哪里、为什么现在值得关注”；
- 说清主营业务适用的主要法律法规、主管机关、法定资质和持续义务；
- 判断持证或履责主体与实际运营、签约、收款、产品、地域及有效期是否匹配；
- 说明集团控股及并表边界、全集团IP基础扫描覆盖率、核心IP分布及重大权属或许可缺口；
- 分别说清A股、港股、美股的主Benchmark和至少两家相邻参照，并解释逐家选择理由、可比维度及可比局限；
- 判断下一轮融资、IPO、海外扩张、业务合作、并购或治理调整的可能性；
- 将商业变化转换为具体、可执行的法律服务需求；
- 提出5至10个体现行业理解的会议问题；
- 形成一套针对该客户而非任何客户均可套用的Pitch切入逻辑。

报告不以“信息最多”为目标，而以以下指标为目标：

- **商业信息密度高**；
- **分析结论明确但不过度确定**；
- **法律服务机会与事实紧密连接**；
- **监管及资质判断有现行法律依据并完成主动核验**；
- **A股、港股、美股各至少3家上市参照，角色清楚、可比局限具体、财务口径统一，且保留可点击来源和官方产品图**；
- **能够帮助律师自然开展客户对话**。

## 五、总执行逻辑

同时运行商业链与法律链，并在Pitch结论处汇合。

商业链：

> 事实 → 商业信号 → 下一阶段决策 → 法律触发点 → 律师Pitch切入 → 建议会面问题

法律链：

> 具体业务行为 → 适用法域与监管事项 → 现行法律规则 → 构成要件及例外 → 法定义务/准入要求 → 应履责主体 → 现有证据 → 匹配判断 → 法律后果 → 整改优先级 → 律师Pitch切入

对重要法律判断采用精简的“规则—事实—适用—结论”结构。先说明规则及适用要件，再将公司业务事实代入；不得从行业标签、经营范围或资质名称直接跳到结论。

完整报告以及第二章、第三章或第八章的研究、起草、更新和复核，必须先完整读取并执行 [法律监管与资质主动调查方法](references/legal-regulatory-analysis.md)，并使用 [法律监管与资质调查矩阵](templates/regulatory_qualification_matrix.md) 建立内部底稿。

完整报告以及第三章的研究、起草、更新和复核，还必须完整读取并执行 [集团范围知识产权调查方法](references/group-ip-investigation.md)，并使用 [集团知识产权范围与清单模板](templates/group_ip_scope_and_inventory.md) 建立集团主体全集、逐主体基础扫描记录和核心IP深度核查底稿。

完整报告以及第六章的研究、起草、更新和复核，必须完整读取并执行 [三市场Benchmark、来源与官方产品图规则](references/market-benchmark-and-source-preservation.md)，并使用 [三市场Benchmark矩阵模板](templates/market_benchmark_matrix.md) 建立A股、港股和美股的最低样本、选择逻辑、可比局限、来源台账和图片资产台账。

示例：

> 公司连续完成多轮融资，并引入地方国资与产业投资人 → 公司已由产品验证转向规模化落地和资本化阶段 → 下一阶段可能涉及区域扩张、投资人权利协调、股权激励及上市准备 → 需要处理治理、历史股权、核心IP归属及上市架构 → 律师可从“提前降低后续融资或上市整改成本”切入 → 询问公司未来18个月资本计划及现有投资人特殊权利安排。

执行时必须持续追问：

1. **So what：** 这项事实对公司经营意味着什么；
2. **Why now：** 为什么该事实在当前时点值得关注；
3. **What next：** 它最可能促使公司下一步做什么；
4. **Legal trigger：** 下一步决策会产生什么法律、监管或交易需求；
5. **Rule：** 哪一现行有效的法律法规、许可目录、监管规则或强制标准支持该判断；
6. **Application：** 公司的具体行为是否落入规则要件，由哪个主体承担义务；
7. **Why lawyer：** 律师能够提供什么不同于财务顾问或普通咨询机构的价值；
8. **How to ask：** 会面时如何把判断转化为不冒犯、但有穿透力的问题。

## 六、工作模式

### 6.1 init

确认目标主体、同名主体、报告基准日、细分赛道、Pitch场景和拟展示的律所能力。

仅在以下事项无法通过工具解决时提问：

- 存在多个高度相似的同名主体；
- 用户未说明拟研究的集团范围且不同范围会明显改变结论；
- 用户要求针对特定法律服务方向Pitch但未说明方向。

### 6.2 intake

读取用户提供的既有报告、名单、PPT、官网材料、融资材料或数据库导出，形成：

- 已有材料清单；
- 可复用事实；
- 原报告中仍然有效的可点击来源和官方产品图及其来源页面；
- 既有MCP结果、查询日期及可复用数据域；
- 需要更新的过时数据；
- 需要MCP或公开渠道补充的缺口；
- 原报告中宣传化、证据不足或缺乏商业分析的内容。

不得因附件已有内容而跳过必要的外部核验，除非用户明确要求仅基于附件。但“外部核验”不等于重新调用企查查：先把有效附件、既有工具结果和查询日期登记为可复用数据，只对缺失、过时或实质冲突的字段补查。

### 6.3 research

围绕八章所需事实，先按“主体 × 数据域”集中检索一次，再将结果映射到各章，并同步建立：

- 计费型MCP查询计划与跨章节共享查询台账；
- 集团主体全集、控制/并表依据及范围状态；
- 实质业务活动与适用法域清单；
- 法律法规及监管口径底稿；
- “应有资质/义务—实有证据—主体与范围匹配”矩阵；
- 全集团IP基础扫描覆盖表、核心IP清单及权属/许可链；
- 事实与数据底稿；
- 商业信号清单；
- Pitch机会清单；
- 高价值会面问题；
- 冲突信息和缺失信息清单；
- A股、港股、美股Benchmark矩阵，以及可点击来源和官方产品图资产台账。

在任何企查查或其他按次、按积分计费的商业数据库调用前，必须完整读取并执行 [企查查计费查询去重与成本控制](references/qcc-query-cost-control.md)。研究按“主体 × 数据域”集中采集，不得按八个章节分别调用。股东、工商变更、董监高、对外投资、融资、资质、IP、司法及处罚等结果一经取得，应写入共享台账并供所有相关章节复用。

同一报告基准日的完整数据采集只执行一次。后续第二章、第三章、第八章以及 `draft`、`check`、`export` 阶段必须消费既有事实底稿、资质矩阵和查询台账；发现缺口时返回 `research`，仅补取尚未覆盖的必要数据。

将法律与资质调查作为前置关卡。在未识别主营业务的监管属性、主要法律依据、主管机关、理论应有资质并主动查询实际持证情况前，不得起草第三章结论。商业数据库没有返回资质信息时，继续查询主管机关、公示平台、企业披露和业务载体，不得直接跳过。

将集团IP调查作为第三章的另一前置关卡。在未建立报告基准日的控股/并表主体全集、未对全部 `in_scope_current` 主体逐一完成基础IP扫描或准确列示未完成范围、未识别核心IP及其权属/许可链前，不得声称“集团知识产权已完整覆盖”“核心IP权属清晰”或形成无保留结论。

### 6.4 draft

生成完整报告。最终正文不得出现：

- 执行蓝图；
- 搜索过程；
- MCP调用过程；
- 内部证据等级；
- “模型判断”“系统推断”等技术性表述。

`draft` 阶段不得直接调用企查查或其他计费型商业数据库。确有新增事实缺口时，先回到 `research` 阶段完成去重检查和调用登记，再继续起草。

### 6.5 update

仅更新指定章节或数据项，同时检查对其他章节的连带影响。例如：

- 新融资可能影响股权结构、商业概况和资本市场判断；
- 新产品可能影响业务情况、IP和同行业对比；
- 新IPO申报可能影响商业概况、融资历史和同行业对比。

若出现新业务、新产品、新客户类型、新收费模式、新法域、新数据流或新经营主体，必须重新执行法律监管与资质前置调查；仅更新融资或团队且业务事实未变化时，可复用仍在有效期内的底稿，但须检查法规和证照是否已修订、到期或变更。

若出现新设、收购、出售、失去控制、首次/不再并表、更名、合并、分立或注销主体，必须先更新集团范围表：新增控股或并表主体补做全部基础IP扫描；退出主体移出当前范围，但与核心IP转让、许可或承继有关的历史链条继续保留。不得因更新报告而对无变化主体重复付费查询。

更新任务必须先载入既有查询台账和已经取得的数据。仅刷新因基准日变化、明确变更信号或用户指定而受影响的数据域，不得因为更新某一章节而重新调用与该变化无关的企查查查询。

更新已有报告时，必须保留仍可访问、与正文事实匹配且来源合格的可点击链接，以及来源明确、内容仍匹配的官方产品图。仅在链接失效、仅指向搜索结果、来源不权威、图片非官方、内容过时或与产品不匹配时替换；不得以“重做排版”为由删除有效证据资产。

### 6.6 check

重点检查：

- 是否仍像数据库摘录而非Pitch KYC；
- 每章是否有明确商业判断；
- 监管结论是否包含现行规则、业务事实、要件适用和结论；
- 是否先形成应有资质清单，再主动收集并核验实有证照；
- 是否核对持证主体、许可范围、地域、产品/场所和有效期；
- 是否建立完整的控股/并表主体清单，并对每个当前范围主体保留逐IP数据域的基础扫描记录；
- 是否区分全集团基础扫描与核心IP深度核查，并核对核心权利的权属、许可、负担、争议和主体匹配；
- 法律服务机会是否来自具体事实；
- 是否出现任何客户都能套用的泛化表述；
- 第六章是否真正完成多市场和多维度比较；
- A股、港股、美股是否各有不少于3家上市参照，且每个市场包含1家主Benchmark和至少2家相邻参照；
- 每家参照是否说明选择理由、比较维度、关键差异和可比局限；
- 可点击来源是否直达所支持的页面，官方产品图是否嵌入文件并附可点击的官方来源。

`check` 阶段不得为了复核相同事实而重新调用企查查。需要新增外部核验时，返回 `research`，仅补查台账未覆盖、已过时或存在实质冲突的数据域。

### 6.7 support

仅补充指定模块，但仍遵守商业化和律师Pitch规则。需要计费数据时先进入 `research` 去重闸门；不得由support模块绕过共享查询台账。

### 6.8 export

生成Word并执行字体、页面、表格、图片、超链接及分页检查。可点击来源必须在Word中保留真实超链接关系，官方产品图必须嵌入文件而非依赖外部热链，并在图片说明中保留可点击的官方来源页面。`export` 阶段仅处理已有内容，不得发起企查查或其他计费查询。

## 七、MCP调用与数据组织

### 7.1 运行时发现

执行前先识别Codex当前可调用的MCP工具，不得把某一特定MCP的函数名称或参数结构写死为唯一实现。

建立以下能力映射：

| 能力 | 首选数据源或MCP类型 | 主要用途 |
|---|---|---|
| 工商主体 | 企查查类、元典MCP、iFind/Wind、国家企业信用信息类MCP | 基本信息、变更、股东、对外投资、分支机构；企查查积分不足时，仅对基础工商及公司概况按覆盖能力切换备用源 |
| 集团主体范围 | 审计报告/年报/招股书、工商控制链、企查查类、元典MCP、iFind/Wind | 建立报告基准日全部直接/间接控制、协议控制及并表主体清单，保留控制路径和并表依据 |
| 法律法规 | 国家法律法规库、政府及主管机关官网、司法机关、交易所与自律组织 | 现行法律、行政法规、规章、规范性文件、司法解释、许可目录、强制标准及监管口径 |
| 资质公示 | 行业主管机关、政务服务、信用及许可/备案/产品注册公示平台 | 主动核验资质名称、编号、持证主体、范围、地域、状态及有效期 |
| 股权穿透 | 企查查类、股权图谱类MCP | 实控人、最终受益人、控制路径、员工平台 |
| 融资事件 | 企查查类、创投数据库、新闻MCP | 融资轮次、金额、投资方、估值及工商验证 |
| 财务估值 | iFinD、Wind、Choice、Bloomberg等MCP | 上市公司财务、估值、市值、分部收入 |
| 证券披露 | 交易所、证监机构、公告检索MCP | 招股书、年报、IPO状态、上市路径 |
| IP | 官方专利/商标/版权公示、专利/商标/软著MCP、企查查类 | 对全部控股/并表主体完成基础扫描；对核心IP核验权利人、法律状态、权属链、许可、质押和争议 |
| 司法与处罚 | 法院、执行、行政处罚、企查查类MCP | 诉讼、执行、失信、处罚及异常 |
| 新闻舆情 | 新闻、网页、企业官网MCP | 里程碑、合作、客户、产能、团队、负面信息 |
| 行业数据 | iFinD、行业数据库、研究报告MCP | 市场规模、增长率、Top企业、市场份额 |
| 文件处理 | Files、PDF、Word、Excel工具 | 读取、核对、改写和导出 |

### 7.2 计费查询去重与成本控制（强制）

企查查及其他按次、按积分计费的数据源必须执行以下规则：

- 在首个计费调用前建立共享查询台账，并列出本次预计的唯一查询；
- 同时使用业务覆盖键和精确调用键：业务覆盖键用于识别不同工具或端点是否已满足同一信息需求，精确调用键用于阻止完全相同的调用；章节名称不得进入任何去重键；
- 相同业务覆盖键已有完整结果时，不得换企查查函数、端点或数据源重复获取；相同精确调用键在同一任务内最多成功调用一次；成功返回空结果记为 `success_empty`，不得原样或同义重试；
- 已有结果能够覆盖所需字段时，直接复用于第一至第八章；不得为了另一章节、另一段表述或补充引用再次调用；
- 仅在主体、数据域、参数范围、基准日或分页确有不同，原响应明确不完整/报错，出现可核验的新变更信号，或用户明确要求刷新时重查；调用前在台账记录理由；
- 工具报错仅允许一次有理由的重试，不得循环重试；需要扩大到非核心主体全量、多层股权穿透或大批量分页时，先说明预计唯一查询数量并征得用户同意；
- 企查查返回积分不足、额度不足或配额耗尽时，记为 `quota_exhausted`，不得写成 `success_empty`、不得原样重试；基础工商或公司信息改用当前可用且能够覆盖所需字段的元典MCP、iFind MCP或Wind MCP补充，任一备用源已满足需求即停止；
- 全集团IP基础扫描属于强制调查目标，但不构成无上限付费授权；先建立主体全集并优先使用官方、免费或能够减少计费数据单元的批量IP来源。需要对非核心主体逐家付费、大量分页或预计调用显著增加时，先列明主体数、数据域、预计唯一调用数和工具明确显示的费用并取得用户确认；未获确认时保留未完成范围，不得降格后仍宣称全量覆盖；
- 工具若返回积分或费用信息，如实记录；未返回时只报告调用次数，不得猜测积分。

完整使用方法、两级去重键、常见数据域复用关系和重查判定见 [企查查计费查询去重与成本控制](references/qcc-query-cost-control.md)，并使用 [企查查查询台账模板](templates/qcc_query_ledger.md) 记录调用。

### 7.3 典型调用顺序

1. 用法定全称、历史名称和统一社会信用代码锁定目标母公司；结合审计报告、年报/招股书、工商控制链及用户材料建立报告基准日的控股和并表主体全集；
2. 归一全部当前范围主体的法定名称、历史名称、英文名称和稳定ID，记录控制路径、并表依据、集团功能及范围状态；
3. 从官网、产品页面、合同角色、招股书/年报、招投标和客户案例拆解实质业务活动、服务对象、载体、地域、数据流和实施主体；
4. 识别每项重要业务的主管机关，检索报告基准日现行有效的法律法规、许可目录、监管口径和强制标准；
5. 先形成理论上的法定资质、批准、登记、备案、报告及持续义务清单；
6. 主动查询主管机关和官方公示平台，并结合企业披露及商业数据库收集母公司和核心子公司的实有资质证据；
7. 核对持证/履责主体、许可范围、地域、产品/场所、有效期与实际运营、签约及收入主体是否匹配；
8. 对全部当前控股/并表主体完成专利、商标、软著及适用IP数据域的基础扫描，再对核心IP及相关持有、研发、运营、许可和历史转让主体开展深度核查；
9. 获取股权、融资、团队、司法、处罚、官网产品、客户、海外布局及近期里程碑，并复用已经取得的IP结果；
10. 按A股、港股、美股分别筛选不少于3家上市参照，每个市场确定1家主Benchmark和至少2家相邻参照，记录逐家选择理由、比较维度、关键差异及可比局限，并用金融MCP批量提取统一口径数据；未上市直接竞品和全球Top企业另表列示，不计入三市场最低样本；
11. 汇总商业信号、法律触发点、资质/IP缺口、Pitch机会及会面问题；
12. 完成报告并进行事实、法律、逻辑、商业化和引用质检。

### 7.4 MCP适配原则

- 企查查类MCP的“疑似实际控制人”“最终受益人”“关联关系”等算法标签只能作为线索，应结合持股、协议、董事席位或公开披露判断；
- 企查查等商业数据库中的资质、许可和处罚信息只能作为发现线索；关键结论须尽量以主管机关、官方公示平台或法定披露核验；
- 商业数据库未返回、官方平台无公开结果或检索失败，不等同于公司未持证或违法；记录查询范围并标注为待核实；
- 先根据业务和现行规则形成“应有清单”，再查询公司“实有清单”；不得将顺序倒置；
- 区分行政许可、批准、登记、备案、持续义务、强制认证、行业/客户准入与自愿认证；不得混称为“资质”；
- iFinD类MCP的行业分类和可比公司推荐只能用于初筛，不能替代业务实质判断；
- 财务指标应尽量批量提取，避免不同公司采用不同期间或数据口径；
- 严格区分“未查到记录”“工具报错”和“企查查积分/额度不足”。积分不足时不得作无记录结论；对基础工商或公司信息，按当前工具能力选择元典、iFind或Wind作为备用源，仅补取缺失字段，不得无差别依次调用全部备用源；
- MCP成功返回为空时，将空结果写入查询台账且不得重复相同计费调用；确需补证时优先转向官方渠道、企业官网及权威媒体，再按数据缺口选择不同且必要的数据源；
- 未完成实际调用前，不得声称数据源不可用；
- 对关键数字保留来源日期和查询日期，以便后续更新。

### 7.5 主体范围

一般工商、司法、团队和商业分析仍按重要性穿透以下主体：

- 主要业务经营主体；
- 核心知识产权持有主体；
- 主要收入或签约主体；
- 主要生产基地；
- 重要境外子公司；
- 员工持股平台；
- 对控制权、融资或未来上市有影响的关联主体。

一般章节不得机械罗列全部小额或无实质业务的子公司。但知识产权调查构成明确例外：必须先建立目标母公司及报告基准日全部直接/间接控制、协议控制和并表主体全集，对每个当前范围主体完成基础IP扫描；再按商业重要性对核心IP持有、研发、生产、运营、许可和历史转让主体开展深度核查。完整主体和扫描记录保留在内部底稿，正文仅呈现重要分布、异常和Pitch意义。

集团边界、范围状态、历史链条及两层IP调查方法见 [集团范围知识产权调查方法](references/group-ip-investigation.md)。

## 八、证据与商业推断规则

### 8.1 证据优先级

1. 现行法律法规、司法解释、主管机关规则及官方许可/执法公示；
2. 专业数据库及交易所文件；
3. 企业官网、官方公众号和投资人公告；
4. 权威财经媒体、行业媒体及研究机构；
5. 一般媒体和转载内容；
6. 自媒体仅作为线索。

### 8.2 KYC与尽调的差异

本报告允许并鼓励基于多个经核验事实形成商业判断。不得因为“无法达到法律尽调级别的确定性”而放弃分析。

可使用：

- “显示……”
- “反映……”
- “意味着……”
- “更可能……”
- “从资本动作看……”
- “结合……判断……”
- “公司现阶段更接近……”

但应避免：

- 无事实基础的确定性预测；
- 将企业宣传中的“唯一、第一、领先、100%”直接写成客观事实；
- 根据融资金额直接推算估值；
- 根据未检索到记录认定事项不存在；
- 根据专利数量直接判断技术领先；
- 根据数据库标签直接认定实际控制关系。

### 8.3 商业判断最低标准

一个重要商业判断原则上应至少基于两类事实，例如：

- 融资轮次 + 产能建设；
- 客户拓展 + 收入结构；
- 海外实体 + 多语种产品；
- 核心IP分布 + 研发团队；
- 同业IPO + 公司治理变化；
- 机构投资人进入 + 股权激励安排。

### 8.4 不确定信息的写法

不得反复使用过多法律式保留，影响报告可读性。只在关键处使用简洁限定：

- “据公司公开披露”；
- “公开资料显示”；
- “现有公开信息不足以确认”；
- “截至报告基准日，公开渠道暂未披露”；
- “该判断仍需结合公司内部财务或合同数据验证”。

### 8.5 法律依据与效力规则

法律或监管判断优先引用正式第一方来源，并记录文件全称、发布机关、效力层级、相关条款、施行/修订日期、有效状态、适用地域及查询日期。

必须：

- 以报告基准日现行有效文本为准，核对修订、废止、过渡期、试点和地方差异；
- 区分法律、行政法规、司法解释、部门/地方规章、规范性文件、强制标准、自律规则、监管问答和行业惯例；
- 将征求意见稿、草案和政策倡议明确标为尚未生效，不作为确定性义务；
- 将法律规则的构成要件与公司具体业务事实逐项匹配，说明适用、较可能适用、待事实确认或暂不适用；
- 对未公开的内部事实提出精准材料需求或会面问题，而不是猜测；
- 对具体处罚或法律后果核对相应责任条款和事实要件后再写。

不得只引用新闻、律所文章、数据库摘要或搜索结果片段支持关键法律结论。

### 8.6 资质信息完整性规则

主动调查资质，而不是等待附件、公司官网或工商数据库提供。对主营收入、核心产品、主要客户、跨境业务或资本计划具有实质影响的每条业务线，必须完成：

> 实质业务 → 主管机关 → 现行依据 → 应有资质/义务 → 实有证据 → 主体/范围/地域/产品/时点匹配 → 缺口或待核实 → 商业影响

查询不到时，保留已查询平台、主体名称、历史名称、关键词和日期，并使用“公开系统未检索到”“系统不提供公开查询”或“待取得内部证照核验”等准确表述。不得将“未检索到”写成“未持有”“无需取得”或“违法”。

## 九、商业化写作规则

### 9.1 写作基调

报告应：

- 像合伙人会前Brief，而不是百科全书；
- 有判断、有重点、有轻重；
- 使用行业术语，但避免堆砌；
- 关注增长、商业化、客户、资本和竞争，而不是只写工商事实；
- 以“事实支持判断”，而不是以形容词制造精彩；
- 对客户保持积极但审慎的基调，既不吹捧，也不刻意找风险。

### 9.2 信息与分析比例

建议总体比例：

- 事实和数据：约40%至55%；
- 商业分析、竞争定位和Pitch启示：约45%至60%。

不得写成90%事实罗列，也不得写成缺乏证据的商业故事。

### 9.3 段落规则

- 每个段落应有一个明确主题句；
- 每列示两至三项事实，应回答一次“这意味着什么”；
- 事实适合使用表格，结论适合使用段落；
- 不要把同一结论在多个章节重复；
- 对近期24个月发生的事项给予更高权重；
- 重要数字必须有时点和口径。

### 9.4 避免空泛表达

不建议：

> 公司投资方阵容豪华，技术实力雄厚，发展前景广阔。

建议：

> 投资人结构已由早期财务投资人扩展至产业资本和地方国资，结合新增生产基地，公司融资用途正由研发验证转向规模交付。这通常意味着下一阶段的重点将从“证明技术可行”转为“证明收入可复制”，并可能同步启动治理规范、股权激励和资本市场路径论证。

不建议：

> 公司拥有36项专利，知识产权储备丰富。

建议：

> 专利数量本身并不足以证明壁垒，应进一步判断核心模型、算法、代码和训练数据是否集中于拟融资或拟上市主体。若核心IP分散于创始人或多家子公司，未来融资和上市前通常需要完成权属归集、许可安排及职务成果文件清理。

不建议：

> 公司业务遍及30多个国家，国际化能力较强。

建议：

> 多语种产品与境外实体同步扩张，说明公司并非仅进行境外销售，而可能已进入本地化交付阶段。对律师而言，真正值得追问的是海外实体的签约功能、数据流向、人员安排及知识产权授权方式，这些事项将直接影响跨境扩张效率和未来资本市场披露。

## 十、律师Pitch价值生成规则

### 10.1 律师优势不是服务清单

不得在每章机械写：

> 律师可提供公司治理、知识产权、数据合规、融资及上市等全方位法律服务。

应写成与客户事实相连接的具体价值：

> 公司核心模型、品牌和海外业务分别由不同主体承载。若公司计划在未来一至两年继续融资或启动上市准备，提前统一核心IP权属、境外授权链条和主要客户合同口径，可显著减少后续尽调阶段的整改工作量。

### 10.2 律师可展示的差异化能力

根据目标客户事实，优先选择以下一至三项，不得全部堆砌：

1. **资本市场路径判断**
   通过同行业上市案例、交易所规则和监管经验，判断公司更可能适合的上市地、时间表、架构和前置整改事项。

2. **交易经验与节奏控制**
   识别融资、并购、战略合作和上市各阶段的文件、治理和监管衔接，帮助管理层减少重复整改。

3. **行业监管翻译能力**
   将复杂业务模式转换为资质、数据、AI、金融、医疗、通信或其他行业监管要求，并提出可落地的业务方案。

4. **股权治理与创始人控制**
   在投资人权利、董事会安排、员工持股、创始人控制和上市规范之间取得平衡。

5. **跨境一体化执行**
   对海外实体、数据流、知识产权、人员、合同和资本安排进行多法域协调，而非仅提供单一法域意见。

6. **知识产权与商业合同落地**
   关注核心IP是否真正支撑商业收入，客户合同、渠道合作、研发合作和授权安排是否可复制并适合融资或上市披露。

7. **风险前置管理**
   不仅指出问题，还说明问题对融资、订单、牌照或IPO的影响，以及何时处理成本最低。

### 10.3 Pitch机会优先级

内部研究底稿应将机会划分为：

- **当前机会（0至6个月）**：正在融资、签重大客户、海外落地、股权调整、争议处理；
- **近期机会（6至18个月）**：下一轮融资、ESOP、合规体系、业务重组、并购、境外扩张；
- **战略机会（18个月以上）**：IPO、上市前重组、跨境资本安排、全球知识产权和数据治理。

仅将高相关机会写入正文。低相关或高度推测事项保留在内部底稿。

### 10.4 关键人映射

将Pitch问题匹配到可能的决策人：

- 创始人/CEO：战略、融资、控制权、上市、海外扩张；
- CFO/董秘：融资、上市准备、财务规范、投资人权利；
- 法务负责人：合同、合规、数据、IP、争议；
- CTO：核心技术、IP权属、开源软件、研发合作、数据来源；
- 海外业务负责人：境外实体、签约、数据流、雇佣及当地监管；
- 机构股东：退出路径、治理权利、资本运作。

## 十一、八章执行规范

## 一、商业概况

### 研究目标

用最短篇幅回答：公司是谁、为什么现在值得关注、处于什么发展阶段、近期资本市场或产业事件释放了什么信号。

### 必须研究

- 成立时间、总部、注册资本及历史名称；
- 核心业务定位及目标客户；
- 最近24个月关键里程碑；
- 产能、研发中心、区域或海外布局；
- 重大客户、政府、产业或科研合作；
- 同行业近半年IPO、递表、上市、并购或大额融资动态；
- 公司是否出现融资、业务重组、治理升级或上市准备信号。

### 商业分析

至少形成以下判断：

- 公司当前阶段：技术验证、商业化初期、规模增长、成熟扩张或资本化准备；
- 近期最重要的增长驱动；
- 为什么目前是律师接触公司的合适时点；
- 公司下一阶段最可能面对的重大决策。

### 律师Pitch启示

优先识别：

- 融资或上市时间窗口；
- 新业务或新区域带来的监管需求；
- 产业合作、重大客户和政府资源对交易结构的影响；
- 公司是否需要将快速增长转化为治理、合同和合规能力。

### 建议会面问题

生成1至3个问题，例如：

- 公司未来18个月最优先的资本或业务目标是什么；
- 新增区域布局主要承担研发、生产、销售还是签约功能；
- 管理层是否已经开始比较境内、香港或美国资本市场路径。

---

## 二、业务情况

### 研究目标

不仅说明“卖什么”，更要说明“客户为什么买、公司如何赚钱、业务能否复制、什么构成真正壁垒”。

### 必须研究

- 产品和服务线；
- 技术参数、性能和应用场景；
- 收入模式：项目制、许可、订阅、SaaS、硬件销售、服务费、效果付费等；
- 客户行业、客户规模及主要采购决策人；
- 获客、交付、续费和收入确认逻辑；
- 核心客户、标杆项目和商业化证据；
- 海外业务和本地化交付；
- 产品路线图及与行业趋势的匹配度；
- 每条重要业务线的具体受监管行为、服务对象、交付载体、经营地域和实际实施主体；
- 可能改变业务法律属性的收费方式、合同角色、数据流、外包/渠道和跨境安排；
- 官网核心产品或场景高清图。

### 商业分析

重点回答：

- 收入未来最可能来自哪一产品或场景；
- 公司是产品公司、项目公司、平台公司还是综合解决方案商；
- 商业模式的可复制性和毛利潜力；
- 客户集中、销售周期及交付成本；
- 技术优势能否转换为合同、收入和续费；
- 海外扩张是真正本地化还是仅渠道销售。
- 哪些产品或交易结构进入特别监管边界，哪些关键事实决定法律是否适用；
- 监管要求会限制产品设计、客户准入、收费、交付或地域扩张中的哪一环节。

### 律师Pitch启示

根据业务识别：

- 核心客户合同和收入确认相关安排；
- 数据、AI、算法、隐私及网络安全；
- 行业准入和外包监管；
- 海外签约、数据流和本地实体；
- 研发、联合开发、渠道和知识产权授权；
- 产品责任、SLA、服务中断及争议分配。

不得只在第三章才讨论监管。第二章应在解释商业模式时说明监管属性，但将完整法律依据、资质清单和匹配结论集中放入第三章，避免重复。

## 三、资质证照及IP

### 研究目标

先依据公司的实质业务判断其依法应遵守的法律法规、主管机关、法定准入及持续义务，再主动收集公司及核心子公司的实际资质证照和履责证据，完成主体、范围、地域、产品/场所和有效期匹配；同时建立报告基准日全部控股及并表主体全集，对全集团完成基础IP扫描，并判断核心技术和品牌是否真正由可融资、可交易的主体控制。

本章不得从现有证照清单开始。必须先回答“公司做什么、法律要求什么”，再回答“公司公开可核验地具备什么、是否匹配”。

### 必须研究

- 报告基准日集团主体全集，包括目标母公司、直接/间接控制、协议控制及实际并表的全部境内外主体，以及控制路径、并表依据、历史名称和范围状态；
- 对每个当前控股/并表主体分别完成专利、商标、软件著作权、核心域名及适用行业特定权利的基础扫描，并记录逐主体、逐数据域的覆盖状态；
- 对核心IP持有、研发、生产、运营、许可、拟融资/上市及历史转让主体开展深度核查；
- 每条重要业务线的具体行为、产品形态、客户、载体、地域、数据流及实施/签约/收款主体；
- 报告基准日现行有效的主要法律、行政法规、司法解释、部门/地方规章、规范性文件、许可目录、监管口径及强制标准；
- 主管机关、监管事项、规则适用要件、例外、豁免、过渡期和地方差异；
- 理论上应具备的行政许可、批准、产品注册、登记、备案、报告、安全评估、强制认证、专业人员/场所条件和持续义务；
- 行业自律、客户供应链及招投标准入与自愿认证，并与法定资质明确区分；
- 主动查询主管机关、政务服务、信用及许可/备案/产品注册公示平台，不得仅依赖企查查或公司自述；
- 母公司、实际运营主体、签约收款主体、生产/研发基地及重要境外主体的资质分布；
- 每项证照或备案的编号、持有人、发证机关、范围、地域、产品/型号/场所、状态、生效/届满日期及官方来源；
- 资质与实际运营、合同、收入、产品、地域和客户的对应关系，以及集团内是否允许共用；
- 查询不到时的检索范围、平台、主体名称/历史名称、关键词和日期，以及需要公司补充的内部材料；
- 专利、商标、软件著作权及核心域名；
- 核心IP权利人、发明人、申请状态及地域覆盖；
- IP共有、许可、质押、无效、驳回、诉讼和职务成果；
- 算法备案、数据来源、开源软件及第三方技术依赖（适用时）。

### 强制调查顺序

1. 拆解实质业务并锁定适用法域与实施主体；
2. 识别主管机关和受监管事项；
3. 检索现行法律规则并分析构成要件；
4. 生成“应有资质/义务”清单；
5. 主动收集“实有证照/履责证据”；
6. 完成主体、范围、地域、产品/场所和时点匹配；
7. 区分已确认、较可能适用、待内部事实确认和暂不适用；
8. 判断对经营、客户、融资、并购或上市的影响，并形成Pitch问题。

使用 [法律监管与资质主动调查方法](references/legal-regulatory-analysis.md) 和 [法律监管与资质调查矩阵](templates/regulatory_qualification_matrix.md)。在完成上述步骤前，不得以“资质齐全”“未发现缺证”或“无需许可”作结。

### 知识产权集团范围与两层调查顺序（强制）

1. 以报告基准日建立全部直接/间接控制、协议控制及并表主体清单；
2. 归一各主体稳定ID、法定名称、历史名称和境外名称，记录控制/并表依据；
3. 对全部 `in_scope_current` 主体按专利、商标、软著、域名/线上标识及适用行业权利逐项完成基础扫描；
4. 依据核心产品、收入、客户、研发、资本计划及异常线索识别核心主体和核心IP；
5. 对核心IP核查权利取得链、职务成果、合作/委托开发、集团内外许可、有效性、地域、质押、共有、冻结、争议、开源和第三方依赖；
6. 核对权利主体、研发主体、运营主体、收入主体及拟融资/上市主体是否匹配；
7. 统计当前集团主体总数、已扫描数、完整/部分覆盖数、待定主体、深度核查主体及未完成原因；
8. 仅将重大分布、异常和商业/Pitch意义写入正文，完整清单保留内部底稿。

使用 [集团范围知识产权调查方法](references/group-ip-investigation.md) 和 [集团知识产权范围与清单模板](templates/group_ip_scope_and_inventory.md)。在完成上述步骤或准确说明未完成范围前，不得以“已完成全集团知识产权核查”“核心IP均由集团完整持有”作结。

### 正文核心表格

对主营业务和重大监管事项原则上列示：

| 业务/产品及实际角色 | 经营主体与法域 | 主要法律依据及相关条款 | 法定要求/主管机关 | 公司现有证据 | 主体/范围/地域/时点匹配 | 待核实或差距 | 商业与Pitch意义 |
|---|---|---|---|---|---|---|---|

第二章识别的每项核心业务原则上应在本表中至少对应一行。即使结论为“根据现有业务事实暂不触发特别行政许可”，也应说明事实前提、检索范围和法律依据；不得无依据写“无需资质”。资质合规映射应先于IP清单表达，避免IP数量掩盖准入调查。

知识产权部分应先说明集团边界与覆盖统计，再以集团IP概览表呈现核心分布：

| 主体/主体类别 | 集团角色 | 主要IP类型 | 与核心业务关系 | 权属及使用安排 | 重大异常或待核实 | 商业与Pitch意义 |
|---|---|---|---|---|---|---|

完整集团主体、逐主体扫描状态和核心IP明细保留在内部底稿，不在正文逐条堆砌。

### 商业分析

不得仅以证书和数量评价，也不得只罗列法律名称。应判断：

- 哪些具体业务事实触发或不触发某项规则；
- 哪些要求是法定许可/备案/持续义务，哪些只是行业或客户准入；
- 哪些资质是进入客户供应链的门槛；
- 持证主体、许可范围、地域、产品/场所和有效期是否覆盖实际业务；
- 公开信息不足时，哪项内部事实会改变适用结论；
- 缺口或错配可能影响持续经营、重大合同、收入、融资或上市中的哪一环节；
- 哪些IP直接对应核心收入和产品；
- 权利是否集中在目标主体或合理的集团主体；
- 核心技术是否容易被替代；
- 资质和IP结构是否适合未来融资、交易或上市。

### 律师Pitch启示

重点连接至：

- 业务监管定性、许可路径和与主管机关的沟通；
- “应有—实有”资质差距排查、持证主体调整、范围扩项、续期及持续义务；
- 新产品、新区域、新客户或收费模式上线前的监管分析；
- 核心IP归集和集团内许可；
- 职务发明、创始人或研发团队权属文件；
- 海外商标、专利和软件许可；
- AI训练数据、开源软件和第三方模型；
- 资质主体与收入主体不一致的整改；
- 融资或IPO尽调前的IP和许可清理。

会面问题应优先询问决定法律适用的关键事实，例如实际功能、服务对象、部署地点、数据类型、合同角色、持证主体和未来扩张，而不是笼统询问“是否合规”。

## 四、股权结构

### 研究目标

说明谁控制公司、投资人如何影响公司、股权结构是否支持下一轮融资和资本化，而不是机械罗列股东。

### 必须研究

- 当前股东、持股比例和历史变更；
- 创始人直接及间接持股；
- 员工持股平台及预留激励池；
- 国资、产业资本、财务投资人和战略股东；
- 董事席位、重大事项权利或公开可见的特殊权利；
- 股权质押、冻结、代持、争议或回购安排线索；
- 对外投资、核心子公司及境外主体；
- 实际控制人及控制路径。

### 商业分析

重点判断：

- 创始人控制是否稳定；
- 投资人结构传递什么产业或资本信号；
- 现有架构是否为下一轮融资留下空间；
- 是否存在治理专业化、股权激励或境内外重组需求；
- 哪些股东可能推动IPO、并购或战略合作。

### 律师Pitch启示

连接至：

- 投资人特殊权利和上市前清理；
- 董事会及重大事项治理；
- 员工持股和股权激励；
- 创始人控制与融资之间的平衡；
- 境内外架构、红筹重组或直接境外上市路径；
- 国资股东相关审批和退出安排。

---

## 五、融资历史

### 研究目标

解释资本为什么投资公司、融资节奏反映什么、资金用于什么，以及下一次资本动作可能是什么。

### 必须研究

- 融资轮次、日期、金额及投资人；
- 工商变更验证；
- 已披露估值及来源；
- 投资人类型：创投、产业资本、地方国资、战略投资人；
- 融资用途；
- 股东进入和退出；
- 债务融资、政府基金或重大补贴（适用时）；
- 同赛道同期融资和估值水平。

### 商业分析

重点回答：

- 资本关注公司的核心逻辑；
- 投资人类型是否由财务资本转向产业资本或地方国资；
- 公司是否从技术验证转向商业化、产能或上市准备；
- 估值与经营数据是否匹配；
- 下一轮融资的可能用途和时间窗口；
- 是否已经出现Pre-IPO信号。

### 律师Pitch启示

连接至：

- 下一轮股权融资；
- 投资人权利协调和历史文件清理；
- ESOP扩容；
- 并购、产业合作或政府投资；
- 上市前重组、规范和监管备案；
- 融资文件、交割条件和后续治理。

---

## 六、同行业对比

### 研究目标

本章是重点。应同时完成竞争识别、上市Benchmark、全球Top对标、财务估值比较、技术差距和资本市场路径分析。

本章必须执行 [三市场Benchmark、来源与官方产品图规则](references/market-benchmark-and-source-preservation.md)，并以 [三市场Benchmark矩阵模板](templates/market_benchmark_matrix.md) 作为内部底稿。A股、港股、美股各不少于3家，三地合计至少9家不同上市公司；每个市场固定包含1家主Benchmark和至少2家相邻参照。未上市直接竞品、其他市场全球Top企业以及同一经济集团的重复上市证券均不计入该最低样本。

不得把所有“概念相关”上市公司均列为同业，也不得仅比较产品名称或市值。

### 6.1 可比公司分层

#### 第一层：直接竞争者

满足以下条件之一：

- 目标客户和采购预算直接重合；
- 核心产品或服务高度相近；
- 在同一招投标、客户名单或细分赛道中直接竞争；
- 相关业务构成公司重要收入来源。

直接竞争者可以是未上市公司，应单独列示。

#### 第二层：上市参照

- 商业模式、收入模式、客户结构或产品形态与目标主体相近；
- 即使不直接竞争，也能提供财务、估值和资本市场参照；
- 每个市场从上市参照中指定1家**主Benchmark**：在核心产品、收入模式、客户结构、技术路线、商业化阶段和资本路径的综合匹配度最高；
- 每个市场另选至少2家**相邻参照**：分别就技术/产品、客户/收入模式、商业化/资本路径等特定维度提供补充，不得把相邻参照包装成直接竞争者；
- 每家公司必须说明“为什么选它”、具体比较维度、关键差异以及该差异如何限制可比结论。

#### 第三层：全球Top企业

- 全球细分市场领先者；
- 代表行业最高商业化、技术或资本化水平；
- 用于衡量长期差距，不得直接等同于当前竞争者。

#### 第四层：替代方案或相邻产业链

仅在其产品可能替代目标主体，或其财务特征对估值有意义时纳入，并明确属于间接参照。

### 6.2 必选市场

分别检索并形成独立表格：

1. A股：不少于3家，1家主Benchmark + 至少2家相邻参照；
2. 港股：不少于3家，1家主Benchmark + 至少2家相邻参照；
3. 美股：不少于3家，1家主Benchmark + 至少2家相邻参照。

某一市场不存在主营业务高度重合的上市公司时，应明确写明：

> 经检索，该市场暂无主营业务与目标主体高度重合的上市公司，以下企业仅作为技术、商业模式、客户结构或资本市场估值的间接参照。

即使没有高度重合公司，仍须完成该市场最低3家样本：选择综合信息价值最高的间接参照作为主Benchmark，再选择至少2家承担不同比较维度的相邻参照。不得为凑数纳入与目标主体缺乏实质比较价值的公司；若采用间接参照，必须在角色名称和可比局限中显著标明。相邻参照的比较维度不得全部相同。

跨市场重复上市的同一经济集团原则上只计入一个市场，不得用同一企业的A/H股或不同存托凭证重复满足最低数量。确需在另一市场讨论其交易或估值差异时，可作补充行，但不计入该市场3家最低样本。

如欧洲或其他市场存在明显全球Top企业，可补充，但不得替代A股、港股和美股。

### 6.3 业务比较维度

至少包括：

- 核心业务及收入来源；
- 主要产品；
- 目标客户及行业；
- 商业模式；
- 境内外布局；
- 技术路线及关键参数；
- 核心器件、模型或平台自主化；
- 收入中相关业务占比；
- 商业化阶段；
- 主要差异；
- 可比局限，包括差异对财务、估值、技术或资本路径比较的具体影响，以及该参照可以和不可以支持的结论。

### 6.4 财务和估值指标

原则上统一提取：

- 最近完整年度营业收入；
- 收入增长率；
- 归母净利润；
- 毛利率；
- 研发费用；
- 研发费用率；
- 最近一期收入和净利润；
- 报告基准日前最近交易日市值；
- PE（TTM）；
- PS（TTM）；
- PB（MRQ，适用时）；
- EV/Revenue或EV/EBITDA（适用时）。

规则：

- 财务期间和估值日必须统一；
- 亏损企业PE写“N/M”；
- 港股、美股须注明原币种及人民币折算口径；
- 未上市直接竞品不虚构财务数据，可用已披露融资、估值、客户和商业化指标；
- 不得仅凭高PE认定技术领先或高估值合理。

### 6.5 分市场表格模板

A股、港股、美股分别使用下表，每张表至少3行且角色完整：

| 公司 | 股票代码 | 可比角色 | 主要比较维度 | 选择理由 | 核心业务 | 与目标主体重合点 | 关键差异 | 可比局限 | 年度营收 | 净利润 | 毛利率 | 研发费用率 | 市值 | PE(TTM) | PS(TTM) | 可点击官方来源 | 财务/估值来源 |
|---|---|---|---|---|---|---|---|---|---:|---:|---:|---:|---:|---:|---:|---|---|

直接竞品表：

| 公司 | 上市状态 | 核心产品 | 主要客户/场景 | 融资或估值 | 商业化进展 | 相对优势 | 相对短板 | 可点击来源 |
|---|---|---|---|---:|---|---|---|---|

“可点击官方来源”应链接至能够直接支持该行核心业务、产品或上市身份的公司官网、投资者关系页面、交易所公告或正式年报页面，不得只写数据库名称、搜索关键词或搜索结果页。“财务/估值来源”应链接至对应期间和估值日的数据页面。Markdown使用 `[来源名称](URL)`；Word必须保留真实可点击超链接。

### 6.6 市场份额与技术差距

市场份额仅在存在可靠行业规模、企业收入或出货量数据时计算。

无法量化时，应基于以下可验证指标判断竞争地位：

- 客户数量和客户层级；
- 标杆项目；
- 收入规模和增长；
- 出货量或交付量；
- 海外收入和地域覆盖；
- 在手订单或续费率；
- 技术参数；
- 第三方测评；
- 资质和标准参与；
- 融资规模和投资人质量。

技术差距应拆分为：

- 底层技术；
- 产品工程化；
- 商业交付；
- 客户生态；
- 海外本地化；
- 财务透明度和资本市场成熟度。

### 6.7 资本市场与律师视角

除财务估值外，应检索可比企业的：

- 上市地和上市时间；
- IPO或递表状态；
- 采用的上市架构或主要资本路径；
- 招股书中重点披露的资质、数据、IP、客户集中、亏损或治理问题；
- 上市后估值表现及市场关注点。

据此判断目标主体：

- 最可能参考哪些上市案例；
- 当前距离资本市场要求的主要差距；
- 未来上市准备的优先事项；
- 律师可以通过哪些同业案例和交易经验建立可信度。

### 6.8 本章最终结论

竞争地位总结必须明确回答：

1. 目标主体真正的直接竞品是谁；
2. A股、港股、美股分别应参考谁；
3. 公司当前优势是技术、客户、全球化、资本还是交付；
4. 公司最明显的短板是什么；
5. 与全球Top企业的差距主要在哪里；
6. 未来两至三年价值提升的关键变量是什么；
7. 哪些变量会自然触发融资、上市、合规、IP或跨境法律需求。

不得仅写“公司具有较强竞争力”或“未来发展前景广阔”。

## 七、创始人及核心团队

### 研究目标

判断谁是公司真正的决策人，团队能否支撑下一阶段发展，以及律师应与谁建立什么类型的沟通。

### 必须研究

- 创始人及核心成员教育、履历和过往业绩；
- 技术、产品、销售、财务、海外及法务负责人；
- 董事会和机构股东代表；
- 关键成员对外任职；
- 团队变动、招聘和组织扩张；
- 发明人、核心技术贡献和商业化经验；
- 管理层公开演讲所反映的战略重点。

### 商业分析

判断：

- 团队是科研驱动、产品驱动、销售驱动还是资本驱动；
- 是否具备从创业公司走向规模企业所需的CFO、法务、国际化和治理能力；
- 是否存在关键人依赖；
- 谁最可能主导融资、IPO、海外扩张或重大合作；
- 管理层的语言偏好和关注重点。

### 律师Pitch启示

- 对创始人强调战略、控制权和长期资本路径；
- 对CFO/董秘强调时间表、规范成本和交易执行；
- 对法务强调业务可落地和跨部门协调；
- 对CTO强调IP、数据和产品机制，而非抽象合规；
- 对海外负责人强调本地签约、数据和多法域执行。

## 八、负面新闻

### 研究目标

识别真正可能影响客户经营、融资、上市或合作的事项，并帮助律师形成有分寸的提问和解决方案，而不是堆砌风险。

### 必须研究

- 行政处罚、经营异常和严重违法；
- 诉讼、仲裁、执行、失信和限制高消费；
- 知识产权、劳动、数据、消费者和产品质量争议；
- 行业监管、牌照、算法、广告、反垄断或出口管制风险；
- 核心客户流失、业务收缩、裁员、融资失败或高管离职；
- 重大负面媒体报道；
- 母公司、核心子公司、实控人和核心团队。
- 每项重大或重要监管事项对应的现行法律依据、违法构成要件、主管机关、处理状态和可能后果；
- 处罚、诉讼或舆情涉及的实际主体是否为目标业务主体，以及事项是否仍具有持续影响。

### 风险分级

- **重大：** 可能直接影响主营业务、融资、上市或控制权；
- **重要：** 需要管理层解释或在交易前处理；
- **一般：** 日常经营争议，对公司整体影响有限；
- **线索：** 信息不足，不宜形成结论。

### 商业分析

- 先区分已生效法律文书、监管调查/立案、媒体线索和一般争议，不得混同；
- 将具体事实代入法律规则和责任要件，说明能够确认什么、不能确认什么；
- 风险是否具有行业共性；
- 是否影响客户、收入、牌照、IP或融资；
- 是否已解决或仍在持续；
- 公司是否具有相应内部管理能力；
- 律师应在Pitch中主动提及、谨慎询问还是暂不展开。

### 律师Pitch启示

不得以风险吓唬客户。应体现“识别问题—判断影响—提出低成本解决顺序”的能力。

例如：

> 公开记录未显示重大信用风险，但公司服务金融客户并开展AI语音运营，其真正需要关注的并非一般合同纠纷，而是客户数据来源、外呼授权、算法透明度和跨境部署。会面时可从业务流程和客户要求切入，而不是直接使用“合规风险”标签。

## 十三、建议会面问题生成规则

问题应：

- 基于报告中已掌握的事实；
- 表明律师做过功课；
- 能引出客户战略、交易计划或痛点；
- 避免在首次会面中像尽调清单；
- 避免询问公开资料已经明确的简单事实；
- 优先使用“未来计划、决策逻辑、安排方式”而非“是否违法”。

高质量问题示例：

- 公司近两轮投资人从财务VC扩展至地方产业资本，未来资本计划更偏向继续融资、产业整合还是上市准备？
- 目前海外实体主要承担销售、本地交付还是客户签约功能？不同国家的数据和知识产权授权是否采用统一模式？
- 核心模型和代码目前集中在母公司还是研发子公司？未来融资或上市时是否计划进行集团内权属归集？
- 公司选择金融和汽车等垂直场景，是基于客户付费能力、数据积累还是产品标准化程度？
- 管理层在比较资本市场路径时，更看重融资规模、估值、上市速度还是海外品牌和客户拓展？

低质量问题示例：

- 贵公司主营业务是什么？
- 贵公司是否有上市计划？
- 贵公司是否重视合规？
- 我们可以为贵公司提供哪些法律服务？

## 十四、最终报告输出规则

### 14.1 标题

```text
[目标主体][细分领域]企业背景调查报告
报告时间：YYYY年MM月DD日
```

### 14.2 每章结构

每章应自然包含：

1. 关键事实和数据；
2. 商业分析；
3. **商业洞察与Pitch启示：** 1至2段；
4. 在report_with_pitch_notes模式下，增加不超过3个“建议会面问题”。

上述内容均属于现有章节内部，不新增一级目录。

### 14.3 引用

- 关键数字、监管事项、融资及财务数据应有来源；
- 每项重要法律、资质和处罚结论应引用能够支持该结论的现行依据或官方公示；
- 法规引用至少记录文件全称、发布机关、相关条款/许可事项、有效状态及查询日期；
- 对修订、废止、过渡期、试点或地域差异作出必要说明；
- 对每家上市参照至少保留一个直接支持核心业务、产品或上市身份的可点击官方来源；财务和估值另附能够支持相应期间及估值日的可点击来源；
- 来源链接必须直达所引用的公告、年报、投资者关系、产品或监管页面，不得使用搜索结果页、无落点的数据库名称或无法复核的首页替代精确页面；
- Markdown统一使用 `[来源名称](URL)`；Word可采用脚注、尾注、括号来源或表格来源行，但必须创建真实超链接关系，不能只显示不可点击的纯文本网址；
- 来源台账至少记录来源标题、发布主体、直接URL、发布日期或资料期间、查询日期及其支持的事实；
- 不需要像法律意见书一样每句话附注；
- 企业自述的核心宣传口径应注明来源；
- 更新报告时保留仍然有效且与事实相符的原有可点击来源；仅替换失效、非权威、错配或仅指向搜索结果的链接；
- 图片注明来源及获取日期，并在图片说明中保留可点击的官方来源页面。

### 14.4 图片

- 第二章优先使用企业官网或官方公众号产品图；
- 图片应与产品或场景直接相关，不使用通用库存图；
- 新报告在能够取得合格官方素材时，通常保留1至3张目标公司的官方产品或应用场景图；更新报告时，来源有效且仍与现行产品匹配的原有官方产品图不得因重排版而删除；
- 第六章可为A股、港股、美股的主Benchmark各保留不超过1张官方产品图或产品对比图，但仅在图片能够实质帮助理解产品差异时使用；相邻参照不强制配图；
- 图片必须来自企业官网、官方公众号、官方投资者材料或交易所披露的企业材料，不得使用搜索缩略图、第三方图库、无来源截图或外部热链；
- Word中的图片必须下载并嵌入文件；图片说明至少包括主体/产品、来源名称、获取日期和可点击的官方来源页面；
- 建立图片资产台账，记录图片文件、对应主体/产品、官方页面、直接图片地址或原始材料、获取日期、使用章节及授权/使用限制线索；
- 官方图片无法取得或无法确认来源时，保留可点击的官方产品页面并明确未配图，不得用第三方图片冒充；
- 不因追求视觉效果挤压商业分析篇幅。

## 十五、Word排版规则

- 页面方向：横向；
- 中文字体：楷体；
- 英文及阿拉伯数字：Times New Roman；
- 正文字号：小四；
- 行距：1.5倍；
- 一级标题加粗；
- 表格表头加粗并设置重复标题行；

## 十六、质量控制清单

### 16.1 目录和用途

- [ ] 是否严格保留八章目录；
- [ ] 是否没有新增综合结论或免责声明；
- [ ] 是否明确服务于律师Pitch前KYC，而非法律尽调；
- [ ] 是否帮助律师理解客户而不是仅展示检索量。

### 16.2 商业化程度

- [ ] 每章是否有明确的“So what”；
- [ ] 是否判断了公司阶段、增长驱动和下一步决策；
- [ ] 是否避免大量工商、专利和诉讼条目的无差别罗列；
- [ ] 是否有足够事实支撑商业判断；
- [ ] 是否避免宣传化和空泛形容词。

### 16.3 律师Pitch价值

- [ ] 法律服务机会是否来自具体商业事实；
- [ ] 是否说明律师在交易节奏、监管、资本市场或跨境执行方面的差异化价值；
- [ ] 是否避免“提供全方位法律服务”等通用话术；
- [ ] 是否识别关键决策人；
- [ ] 是否形成高价值会面问题。

### 16.4 第六章专项

- [ ] 是否识别未上市直接竞品；
- [ ] 是否分别覆盖A股、港股、美股，且每个市场不少于3家、三地合计至少9家不同上市公司；
- [ ] 每个市场是否明确1家主Benchmark和至少2家相邻参照，相邻参照是否承担不同的比较维度；
- [ ] 未上市直接竞品、其他市场全球Top以及跨市场重复证券是否未被计入三市场最低样本；
- [ ] 无高度重合公司时是否明确说明并采用最具信息价值的间接主Benchmark，而非用无关公司凑数；
- [ ] 是否统一财务期间、币种和估值日；
- [ ] 是否区分直接竞品、主Benchmark、相邻参照和全球Top；
- [ ] 每家公司是否说明选择理由、比较维度、关键差异和具体可比局限，而非统一写“可比性有限”；
- [ ] 每家公司是否至少保留1个可点击官方来源，并对财务/估值数据保留对应期间和估值日的可点击来源；
- [ ] 三个市场主Benchmark的官方产品图是否按实质需要保留；未配图时是否保留官方产品页并说明原因；
- [ ] 是否分析技术、商业化、客户、全球化和资本市场差距；
- [ ] 是否将同业IPO和招股书问题转换为目标客户的Pitch启示。

### 16.5 事实和时点

- [ ] 主体、历史名称和子公司是否区分；
- [ ] 股权和融资是否使用同一时点；
- [ ] 财务和估值是否使用统一口径；
- [ ] 是否区分已完成融资、已宣布融资和媒体传闻；
- [ ] 是否将未检索到误写为不存在；
- [ ] 是否核对企业宣传中的唯一、第一、领先等表述。

### 16.6 法律分析专项

- [ ] 重要法律结论是否包含规则、事实、适用和结论，而不是只列法规名称；
- [ ] 是否使用报告基准日现行有效的正式文本并核对效力层级、修订和地域；
- [ ] 是否区分法律法规、监管口径、强制标准、自律规则和行业惯例；
- [ ] 是否将草案、征求意见稿或政策倡议误写为现行义务；
- [ ] 是否避免仅用新闻、律所文章或商业数据库支持关键法律结论；
- [ ] 具体处罚或法律后果是否有责任条款和事实要件支持。

### 16.7 资质主动调查专项

- [ ] 是否先拆解实质业务并形成“应有资质/义务”清单；
- [ ] 是否识别主管机关并主动查询官方许可、备案或产品注册公示渠道；
- [ ] 是否覆盖母公司、实际经营、签约收款、生产/研发及重要境外主体；
- [ ] 是否区分行政许可、备案、持续义务、强制认证、行业/客户准入和自愿认证；
- [ ] 是否核对持证主体、范围、地域、产品/场所和有效期；
- [ ] 是否将官方或商业数据库“未检索到”错误写成未持有、无需取得或违法；
- [ ] 是否把公开信息不足转化为具体材料需求或高价值会面问题；
- [ ] 第三章是否说明资质或监管事项对经营、客户、融资、并购或上市的具体影响。

### 16.8 集团知识产权专项

- [ ] 是否以报告基准日建立全部直接/间接控制、协议控制及并表主体清单，并保留控制或并表依据；
- [ ] 是否区分当前集团范围、历史IP链条、范围待定主体及非控制参股主体；
- [ ] 是否对每个 `in_scope_current` 主体分别完成专利、商标、软著及适用IP数据域的基础扫描；
- [ ] 是否使用稳定主体ID合并历史名称和别名，避免漏查或重复计算；
- [ ] 是否根据产品、收入、客户、研发和资本计划识别核心IP，而非仅按数量判断；
- [ ] 是否对核心IP核查权属链、职务成果、许可、有效性、地域、共有、质押、冻结、争议、开源和第三方依赖；
- [ ] 是否核对权利、研发、运营、收入及拟融资/上市主体之间的匹配；
- [ ] 是否披露集团主体总数、扫描覆盖数、部分覆盖或未完成范围，而未把公开未检索到写成不存在；
- [ ] 是否将完整清单保留底稿，仅在正文呈现重大分布、异常和Pitch意义；
- [ ] 全集团扫描是否执行批量优先、两级去重和付费扩展确认。

### 16.9 计费查询成本控制专项

- [ ] 是否在首个企查查或其他计费型MCP调用前建立共享查询台账；
- [ ] 是否按“主体 × 数据域”集中采集，而不是由各章节分别查询；
- [ ] 股东、董监高、对外投资、融资、IP、司法和处罚等结果是否已跨章节复用；
- [ ] 是否不存在相同去重键的重复成功调用；
- [ ] 是否同时检查业务覆盖键与精确调用键，避免通过更换企查查函数重复取得相同信息；
- [ ] 成功返回的空结果是否已复用而未原样重试；
- [ ] 企查查积分不足是否标为配额状态，并已按需转用元典、iFind或Wind补充基础公司信息，而非写成无记录；
- [ ] 每次重查是否符合允许条件并在调用前记录理由；
- [ ] 是否记录唯一计费调用次数、复用次数及工具明确返回的积分信息。
- [ ] draft、check和export阶段是否没有直接发起计费查询；需要补查时是否先返回research执行闸门。

### 16.10 来源、图片与导出完整性

- [ ] Markdown中的来源是否均为可点击链接，且直达支持相应事实的页面；
- [ ] Word中的来源是否建立真实超链接关系，导出后是否抽查链接目标而非仅检查蓝色文字；
- [ ] 更新报告时是否保留了仍有效的原有可点击来源和官方产品图；
- [ ] 官方产品图是否来自可核验的企业官方页面或正式披露，且已嵌入Word而非使用外部热链；
- [ ] 每张图片说明是否包含主体/产品、来源名称、获取日期和可点击官方页面；
- [ ] 来源台账和图片资产台账是否足以让他人在不重复研究的情况下复核或更新。
